# 单机版本化 KV 与锁

本模块实现 [6.5840 KV 实验](https://pdos.csail.mit.edu/6.824/labs/lab-kvsrv1.html)：
单机内存 KV 在网络丢请求、丢回复和延迟消息时提供条件写入，再用它实现客户端互斥锁。
RPC 类型和公共接口沿用课程骨架；仅使用 Go 标准库和已有课程设施，无新增依赖。

## 状态与不变量

Server 的权威状态为 `map[string]entry`，每项包含 value 和 version。全局互斥锁
保护读取、版本比较及替换；不在锁内执行 RPC、等待或重试。

| 请求 | 条件 | 结果 |
| --- | --- | --- |
| Get | key 不存在 | `ErrNoKey`，value 为 `""`，version 为 0 |
| Get | key 存在 | `OK`，返回同一个条目的 value/version |
| Put | key 不存在，输入版本为 0 | 创建条目，版本为 1，返回 `OK` |
| Put | key 不存在，输入版本非 0 | `ErrNoKey` |
| Put | key 存在，版本不同 | `ErrVersion` |
| Put | key 存在，版本相同 | 替换 value，版本加一，返回 `OK` |

成功写入恰好递增一次版本，失败写入不改变状态。空 key 和空 value 都是合法数据；
通过 map 的存在标记区分不存在与空值。状态不包含每客户端的历史或去重表。

成功 Put 的线性化点为锁内替换条目的时刻，Get 和失败 Put 的线性化点为锁内读取、
判定状态的时刻。互斥锁使版本比较与更新不可分割，同一 key 同一版本最多一个写入成功。

## Clerk 与最多一次写入

每次调用使用独立的参数、回复与重试状态。RPC 返回 false 只表示没有收到回复，不能证明
请求未执行；等待 100ms 后重发相同参数，收到有效回复后结束。Put 始终保留原版本：

- 首次 RPC 收到 `ErrVersion`：返回 `ErrVersion`，可确定该调用没有写入。
- 此前 RPC 失败，重发收到 `ErrVersion`：返回 `ErrMaybe`，可能写入零次或一次。
- 收到 `OK` 或 `ErrNoKey`：直接返回对应结果。

例如版本 7 的写入成功、回复丢失后，重发版本 7 会被当前版本 8 拒绝。
Server 不生成 `ErrMaybe`；它是 Clerk 对结果不确定性的表达。
与维护客户端请求结果表相比，版本条件写入不需要按客户端增长的服务端状态，代价是
调用者必须处理 `ErrMaybe`，不能获得每次写入的确定结果。

Get 可以安全重试，返回最后一次收到的有效读取结果。各次读取都发生于该 Clerk 调用期间。
Put 若实际写入，其线性化点取成功写入处；若始终未写入，则取版本冲突判定处。
`ErrMaybe` 允许这两种结果，不代表写入确定失败，也不代表“恰好一次”。

## 锁协议

每个 Lock 实例保存 lockname 和 `kvtest.RandValue(8)` 生成的稳定所有者 ID。
key 直接使用 lockname；不存在或 value 为 `""` 表示空闲，否则 value 表示所有者。
释放通过写入空值完成，不删除条目、不重置版本。

Acquire 读取锁状态，对不存在或空闲条目用读到的版本条件写入自己的 ID（不存在时用 0）。
`OK` 表示成功；冲突或 `ErrMaybe` 后重新读取。读到自己的 ID 即确认持有，
读到其他 ID 则等待。竞争或结果不确定时每轮等待 100ms，避免忙轮询。

Release 先读取所有者；仍是自己时才按该次读取的版本条件清空。`OK` 后结束；
冲突或 `ErrMaybe` 后重新读取，若已空闲或属于别人就结束。
这使“释放已执行但回复丢失，随后别人已获取”不会变成清除新持有者的写入。

获取和释放的状态转换点分别是成功写入 ID 和空值的时刻。
同一版本只有一个竞争写入能成功；其他客户端在持有者释放前不能改变其条目，
所以获取结果不确定后可以用所有者 ID 确认归属。迟到的获取、释放 RPC 保留旧版本，
无法修改后续持有周期，即使 value 再次变回空闲也不会出现版本复用。

## 假设与边界

- 服务端和客户端不崩溃；状态不持久化，不支持重启后的身份或数据恢复。
- 版本在运行期间不回绕；所有者 ID 不冲突（随机 ID 仅使冲突概率很低）。
- 锁 key 专用于协议，业务代码不能直接改写；不同名称表示不同锁。
- 同一 Lock 实例按 Acquire/Release 顺序使用，不支持重入、并发调用或跨实例释放。
- 没有租约、取消、超时返回、公平性或无饥饿保证。持有者不释放会阻塞其他客户端。
- 安全性依赖上述协议与不变量；完成调用还需要网络恢复、持有者释放和调度机会。

仓库入口中“租约锁”的描述不代表本模块实现了租约；课程明确把客户端崩溃排除在范围外。

## 验证

在 `6.5840/src` 下运行：

```sh
make kvsrv1
make lock1
```

两个目标默认使用 `-race`，且会先构建测试所需的服务端进程。
新增 `TestServerStateTransitions` 检查空输入、错误分类、失败不改状态、重复请求、
迟到获取/释放和不同 key 的独立状态；锁的脚本化测试检查 `ErrMaybe` 后写入发生与
未发生的两种情况，以及释放结果不确定后所有权已转移时不再写入。
这些脚本验证应用层决策，不替代真实网络测试。

课程测试另外覆盖可靠网络、并发竞争、不可靠网络、多个锁和多客户端内存使用。
Porcupine 检查仅覆盖所记录的历史；其现有 Get 模型只检查 value，未充分检查版本和
错误分类，由状态转换测试补足。检查超时返回 Unknown 不能记作确认线性化，race
检查通过也不构成所有执行均正确的证明。

2026-11-11，Go 1.23.5 / Linux amd64 实测：

| 命令 | 结果 |
| --- | --- |
| `make kvsrv1` | 全部 5 个测试通过，测试包耗时 112.520s |
| `make lock1` | 全部 8 个顶层测试通过（含 4 个脚本化子测试），测试包耗时 17.330s |

两次运行均启用 `-race`，没有报告数据竞争。并发 Put 与单客户端不可靠网络测试调用了
Porcupine，本次输出没有非法历史或超时提示，即这些历史得到 Legal 结果。
以上结果只对应本次运行和测试覆盖的故障模型，未验证崩溃恢复、版本回绕或随机 ID 冲突。
